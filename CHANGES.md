# Изменения 0.10.9 — нативные одиночные слои и fallback рамок

## Одиночные слои

- Одиночный shape-слой больше не конвертируется в Smart Object перед раскладкой. Пиксельные слои и уже существующие Smart Object также остаются без преобразования.
- Smart Object создаётся только когда он нужен как единый объект: для выбранной группы или транзитивно связанного набора слоёв. Текст внутри таких наборов по-прежнему используется для имени итогового объекта.
- Проверки `collectLayoutItems` и перед Apply расширены на Photoshop `layerKind == 4`, поэтому shape-слои проходят обычный расчёт `boundsNoEffects`, общий transform и move напрямую.
- Временный превью-анализ при необходимости всё ещё может внутри отдельного History-состояния преобразовать слой в Smart Object; после восстановления истории исходный тип слоя не меняется.

## Пустые результаты Python

- Добавлен отдельный per-run breaker для корректных, но бесполезных результатов анализа изображений. Это не техническая ошибка: учитываются последовательные слои, на которых все запрошенные признаки не дали полезного пола, позы или палитры (`not_applicable`/`uncertain`).
- Порог — 3 подряд пустых слоя. Полезный M/F по фотографии, подтверждённая поза или валидная палитра сбрасывают счётчик.
- После срабатывания дальнейшие JPEG-превью и `analyze_image` не выполняются до конца запуска. Одновременно выключается optional Python-packing; заполнение считается геометрическим ядром JSX.
- Результаты, полученные до breaker, не уничтожаются. Пол, уже определённый по имени слоя пакетным `gender_names`, остаётся доступен JSX-алгоритму М/Д. Это сохраняет полезную сортировку рамок с именами без дальнейшего анализа их «фотографии».
- Технические ошибки и новый empty-breaker независимы: прежние feature circuit breaker'ы пола/позы/цвета сохранены.

Регрессии: одиночный shape остаётся `convert=false`; три подряд no-face/no-color/no-pose ответа делают только три покадровых запроса вместо полного прохода, отключают Python-packing и не помечают feature-breaker'ы технической ошибкой; пол, найденный по имени до fallback, сохраняется.

# Изменения 0.10.8 — устойчивость позы и белой одежды

## Поза: плавное влияние корпуса

- Удалён дискретный порог `|body yaw| < 12° → 0`, из-за которого 11,9° и 12,0° могли радикально менять итоговый порядок.
- Сила направления корпуса теперь плавно растёт через `smoothstep` в диапазоне 6–18°; 12° находятся в середине перехода.
- При почти фронтальном корпусе подтверждённый поворот головы больше не уменьшается автоматически до 30%. При нулевом yaw корпуса голова сохраняет 100% своего значения; при сильном yaw корпуса плавно возвращается прежняя композиция 70% корпус / 30% голова.
- Противоположные направления также получают плавный `pose_conflict_strength`; при сильном конфликте корпус, как и раньше, получает приоритет, но без нового скачка ровно на 12°.
- При отсутствии надёжной головы слабый body yaw плавно затухает к нулю вместо включения одним порогом.

Регрессии проверяют сохранение 6° головы при фронтальном корпусе и близость результатов для 11,9°/12,0°.

## Цвет одежды: белая одежда не является подписью

- Старый алгоритм принимал первые 8 почти полностью белых строк ниже лица за начало подписи. На белой одежде/белом фоне это могло обрезать почти всю область груди и вернуть «цвет не определён».
- Теперь белая область считается подписью только при устойчивом полноширинном белом run после заметного перехода от менее белого фотографического содержимого.
- Если переход не подтверждён, область не обрезается: лучше оставить небольшую часть белого поля в выборке, чем потерять настоящую белую одежду.
- Добавлена регрессия с широкой белой областью сразу под лицом и отдельная проверка настоящего белого footer.

# Изменения 0.10.6 — симметрия рядов и цвет по всему листу

- При невозможности строгого М/Д-черёдования выбирается симметричный порядок с минимальным числом одинаковых соседей. Для 4 М + 2 Д — МДММДМ; для 2 М + 4 Д — ДМДДМД. ММДДММ не выбирается, когда доступен симметричный вариант с меньшим количеством повторов.
- Для известных полов шаблон ряда рассчитывается динамическим программированием по зеркальным парам: минимум повторов → минимум несовпадающих зеркальных пар → близость меньшинства к центру. Учитываются все допустимые сочетания при заданной квоте, результат кэшируется. Если полная симметрия невозможна по количествам, выбирается минимальная асимметрия. Сбалансированные ряды продолжают строго чередоваться. Для неопределённого пола остаётся ограниченное локальное улучшение без выдумывания М/Д.
- Квоты между рядами и итоговый semantic optimizer учитывают новую симметрию. Порядок приоритетов итоговой расстановки: геометрия → минимум повторов/максимум известных чередующихся пар → симметрия несбалансированных рядов → центральность меньшинства → межрядное чередование → поза. Итоговый оптимизатор проверяет также обратные варианты и обмены между рядами. При разных размерах фотографий допустимость каждой перестановки проверяется геометрически.
- Одинаковая семантическая обработка выполняется после геометрии JSX и после декодирования геометрии Python. Python не имеет второй независимой реализации пола/цвета; расстановка идёт через общий JSX-оптимизатор. Единый масштаб, интервалы, число фотографий в рядах и проверка выделения сохранены.
- В списке цвета: «Не учитывать», «Согласованные цвета», «Максимальный контраст». Согласование уменьшает различие палитр у соседей; контраст увеличивает. Оба режима оценивают весь лист по фактическим координатам: ближайший справа на той же линии и ближайший ниже; вес горизонтального соседства 1, нижнего 0.5. Обмены возможны между любыми рядами и площадками, а не только внутри ряда. Неизвестная палитра не подменяется цветом.
- Глобальная начальная сортировка для согласования — лишь кандидат; окончательный критерий — близость палитр соседей, а не направление светлое/тёмное. Для больших наборов каждый объект участвует в поиске с распределёнными по всему листу партнёрами (16 на проход), до 8 проходов. Это ограниченный поиск, без гарантии абсолютного глобального минимума/максимума всех перестановок.
- Цвет больше не требует математически неизменной стоимости позы. В каждой позиции допустим портрет с эффективным поворотом в пределах 12° от исходного, наклоном в пределах 8°, с тем же статусом достоверности. Все сравнения идут с исходным результатом расстановки по позе, поэтому допуски не накапливаются от обмена к обмену. Портрет с выраженным поворотом (от 12°), направленным внутрь, не переносится на сторону, где он будет смотреть наружу. Геометрия и показатели М/Д, симметрии, центральности и межрядного чередования не ухудшаются ради цвета. Порог — композиционная настройка, а не оценка точности модели.
- Прежние четыре направления цвета в настройках и экшенах переходят в «Согласованные цвета». «Максимальный контраст» и «Не учитывать» сохраняются. UUID экшена и зависимости прежние. Серверу обновлён номер версии для штатного перезапуска; анализ изображений/модели не изменены.

Проверено: 16 JSX-наборов проходят; 7 Python-наборов без дополнительных зависимостей проходят. Новые проверки: 50 сочетаний количеств против полного перебора всех строк длиной до 12; итоговые симметричные ряды с позой/без неё; настоящая геометрия Python и JSX для двух островов с рядами МДММДМ; оба режима цвета между рядами и островами, полезные обмены при близкой позе, защита сильных поворотов, участие всех 96 фото в ограниченном поиске; миграция/сохранение настроек. Существующие проверки History, подготовки групп/linked, Actions и отмены проходят на API-моделях. Синтаксис JSX/Python и кодировки проверены.

Ограничения: Photoshop/Windows здесь недоступны. Шесть Python-наборов анализа изображений/словарей не запустились из-за отсутствия cv2 в текущей среде; повторной проверки реальных моделей и палитр не было. Их код не менялся. Симметрия оценивается по порядку полов в ряду; при разных ширинах фото зеркальные расстояния могут отличаться. Для разных размеров и неопределённого пола общий поиск остаётся ограниченным. Исторические отчёты ниже относятся к прежним релизам.

Обновление с 0.10.4/0.10.5: заменить JSX и PYW из Photoshop-files. Повторная установка runtime не нужна, если зависимости 0.10.4 уже установлены.

# Изменения 0.10.5 — группы, связанные слои и рамки

- Группировка рядов больше не передаёт имя «Ряд N». Photoshop сам назначает стандартные имена групп. По той же схеме создаётся временная группа для связанного набора.
- Входные группы конвертируются в Smart Object. Если выбраны группа и её дочерние слои, получается один объект, а не дубли. Связи слоёв (иконка цепочки, linkedLayerIDs) обходятся транзитивно, включая невыбранные связанные слои, обратные связи и связи изнутри выбранных групп. Набор объединяется в группу и конвертируется в один Smart Object. Внешний linked-файл уже существующего Smart Object не является этой связью: он остаётся обычным входным Smart Object.
- Все текстовые слои внутри подготавливаемого набора, в том числе во вложенных группах, читаются через textKey ActionDescriptor. Имя нового объекта — содержимое в порядке сверху вниз панели, пробельные переносы нормализованы, одинаковый текст не повторяется. Если текста нет, сохраняется подходящее исходное имя (приоритет Smart Object/пиксельному слою перед рамкой/пустым текстовым слоем). Текст не подставляется в исполняемые строки, переименование — через ActionDescriptor.
- Подготовка автоматическая. Обычные пиксельные слои/Smart Object работают как прежде; отдельные векторные shape-слои предварительно конвертируются, поэтому цветные векторные рамки тоже допустимы. Отдельный несвязанный текст/коррекция остаётся неподдерживаемым входом: включите его в группу/связанный набор. Артборд не преобразуется как обычная группа.
- Обход структуры адаптирован по приложенному пользователем «Layers - parse layers pallette to object.jsx». Один полный executeActionGet-дескриптор на индекс, bottom-up границы layerSection, сохранён parentId. Все новые чтения/выбор слоёв, создание групп, Smart Object и переименование — ActionManager. DOM не используется для обхода layers/grouped/linkedLayers/textItem или преобразования слоёв. Существующие Document.suspendHistory/activeHistoryState и однократный app.refresh после временной подготовки сохранены для транзакции/корректных якорей истории.
- Преобразования сначала выполняются временно для измерений и семантики. Перед итогом восстанавливается исходная история, затем подготовка и Apply выполняются в одном suspendHistory Auto layout. Повторные объекты сопоставляются по порядку единиц подготовки; проверяются имя, ширина, высота и исходное положение (0.05px). Новые ID переносятся в позиции и элементы рядов, исходные размеры/общий масштаб сохраняются. Отклонение/отмена откатывает всё к исходным группам, тексту, связям и выделению. Запись action-профиля остаётся только после успеха. Итог не оставляет отдельно применённого шага подготовки.
- Цена единого Undo: преобразование групп/связей выполняется дважды, временно и окончательно. Большие группы могут заметно увеличить время; обычные фото без подготовки второй раз не преобразуются.
- Предварительные проверки до модификаций: отсутствие ID связи, блокировки выбранных корней/родителей, пустая группа, разные непосредственные родители у связанного набора, неполная обтравочная цепочка, не изолированные коррекции/нестандартное наложение внутри Pass Through. Наборы из разных родительских групп требуют сначала собрать их в одном контейнере; скрипт не переносит автоматически посторонние маски/эффекты и не игнорирует эту неоднозначность. Изоляция оценивается только по группам ВНУТРИ будущего объекта, не по невыбранному родителю.
- Отсутствие лица теперь штатный not_applicable, не ошибка фото/сервера: рамки в начале списка не отключают анализ следующих портретов. Пол рамки может определиться по текстовому имени; поза и палитра одежды без лица остаются неизвестными. Цвет самих рамок этот режим не сортирует. Технические ошибки по-прежнему ограничиваются circuit breaker.

Проверки: 15 JSX-наборов и 13 Python-наборов проходят. Новые тесты — дедупликация групп/потомков, связи из потомка, связанные невыбранные слои, структура с фоном/вложенными группами, имя из текста, фильтр опасных контейнеров/обтравки/коррекций/наложения; реальный main + временная подготовка + финальное применение на модели History, новые ID, М/Д/поза/цвет, фиксированные метрики экшена, обычное фото вместе с группами, группировка рядов без имён; отмена в обоих преобразованиях и Move, отказ при отличающихся размерах, единый Undo-модель; пять no-face рамок перед портретом не отключают признаки. Настоящий YuNet не нашёл лица на пяти цветных прямоугольных рамках. Синтаксис Python, CRLF BAT без BOM, BOM JSX и ссылки BAT-меток проверены.

Ограничение проверки: Photoshop недоступен, поэтому новые ActionManager-команды и настоящую историю/Undo/видимость/внешний вид групп здесь выполнить нельзя. API-модели проверяют алгоритм и транзакцию, но не заменяют проверку на реальном Photoshop. Сложные связки с разными родителями/зависимыми коррекциями намеренно останавливаются до изменений.

Обновление с 0.10.4: заменить JSX и PYW. Installer revision 4, пакеты/модели прежние; повторная установка не нужна, если runtime 0.10.4 уже обновлён.

# Изменения 0.10.4 — автономные словари russiannames

- Добавлены russiannames 2.0.0 и DuckDB 1.4.4, дополнительно к pymorphy3. Закреплённые версии устанавливаются в приватный venv. Словари names/surnames/midnames входят в wheel russiannames; ни внешняя БД, ни API, ни отдельные файлы в Photoshop не нужны. DuckDB — встроенный движок в том же процессе Python.

Неопределённость явно найденного неоднозначного/противоречивого имени не отменяется произвольной догадкой морфологии; дальше возможен прежний анализ фото.

# Auto Layout 0.8.1 — совместная композиция М/Д, корпуса и головы

## Что исправлено

1. При дисбалансе пола внутри ряда меньшинство больше не расходуется от первого края. Для подтверждённых M/F без U строится центральный чередующийся блок, а остаток большинства делится между двумя краями. Например 1 М / 4 Д: `Д Д М Д Д`. При 2 Д / 4 М выбирается `М М Д М Д М` или его зеркало. Для U применяется локальное улучшение без ухудшения существующего чередования. При разных размерах дополнительная оценка центральности использует реальные X детей и центр содержимого ряда, а не только номера столбцов.
2. Вместо строго закреплённых слотов работает optimizeSemanticAssignment: каждый кандидат оценивается как целая раскладка после реального пересчёта размеров и координат. Рассматриваются сортировка подтверждённых поз, обмены между рядами и альтернативные схемы внутри ряда.
3. Снято ограничение одинаковой высоты каждого исходного ряда. Полезный обмен разновысоких фотографий разрешён, если их новые высоты помещаются при том же общем scale и gap Y. Вертикальное положение/высота рядов могут измениться. Число рядов и фотографий по рядам, общий scale, gaps и назначение площадкам сохраняются.
4. Начало М/Д в ряду может измениться. Между разными рядами обмениваются только дети одного пола, так что M/F/U-количество каждого ряда сохраняется. Внутри ряда возможны обмены между разными полами, только если не ухудшаются более приоритетные критерии.

## Приоритеты

- Сначала допустимость геометрии при прежнем общем масштабе.
- Затем фактическое чередование известных M/F внутри рядов.
- Затем центральность меньшинства в несбалансированных рядах.
- Затем соответствие направления позы месту и плавность направления слева направо.
- При равенстве — межрядное чередование.

Это ограниченный совместный поиск, не доказанный глобальный оптимум всех перестановок. До 12 проходов; в наборах до 80 объектов проверяются все допустимые пары, для более крупных наборов пары ограничены наиболее проблемными и распределёнными по раскладке позициями. Глобальная сортировка одинаковых размеров и проверка вариантов рядов сохраняются. Полная quadratic validation выполняется для победителя; промежуточные кандидаты проверяют контейнеры, диапазоны, ширины и высоты, что сокращает повторную работу.

## Корпус как основной признак

Настройка называется **«учитывать разворот тела и головы»**; прежний сохранённый considerHeadTurn используется без потери настройки.

Добавлен MediaPipe Pose Landmarker Full. Используются world landmarks плеч: RIGHT_SHOULDER = 12, LEFT_SHOULDER = 11. Для разворота оценивается разность глубин плеч относительно проекции плечевой линии. Проверяются видимость/presence обоих плеч >= 0.8, расположение внутри изображения, минимальная ширина плеч 40 px, допустимая геометрия плеч и соответствие позы найденному лицу. Сопоставление по носу с YuNet ROI предотвращает выбор другого человека в фоне.

Оценка повторяется на зеркальной копии JPEG, созданной **в памяти**. Приведённые к исходному знаку углы должны расходиться не более чем на 20°. Итоговый body yaw — среднее. Более слабые развороты тела, |yaw| < 12°, считаются нейтральными. Для головы сохраняется прежний порог 8°. Если оба признака надёжны, композиционный turn = 0.7 × body_turn + 0.3 × head_turn. Вес 0.7 — композиционное предпочтение, не вероятность точности модели. При ненадёжной голове используется валидный корпус с весом 1. При ненадёжном корпусе сохраняется прежняя голова. Противоречащие направления могут частично компенсироваться — итог отражает преимущественно корпус.

В отличие от 0.8.0 сортировка не использует только yaw головы. В оптимизаторе квадратичная стоимость назначения к общему centerX дополнена штрафом за обратные скачки направления в ряду (0.35 × сумма квадратов таких скачков). Это не математический запрет каждого локального нарушения: схема М/Д и центральность меньшинства важнее, неизвестные позы остаются нейтральными.

Поворот тела по одиночной фотографии — оценка модели, не измерение с гарантированной точностью. Особенно сложны обрезанные плечи, вид со спины, скрытые части тела и необычные позы. Фильтры отбрасывают часть таких случаев, но не гарантируют обнаружение каждого неверного результата.

## Runtime и совместимость

Установщик revision 3 добавляет `pose_landmarker_full.task`, SHA-256:

`5134a3aad27a58b93da0088d431f366da362b44e3ccfbe3462b3827a839011b1`

Источник: `https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_full/float16/1/pose_landmarker_full.task`.

Версии Python/NumPy/OpenCV/MediaPipe/JAX прежние. Новых пакетов сверх 0.8.0 нет. Без body-модели продолжается работа по голове, UI показывает соответствующую подсказку. Без Python обычная геометрия остаётся полностью доступной. Сервер: `auto-layout/0.8.1`.

Одно превью и одно чтение JPEG сохраняются. Full Pose выполняет два inference (оригинал и зеркало в памяти); это увеличивает время анализа. Все модели переиспользуются в памяти. Между inference проверяется отмена. Ошибка корпуса не отключает успешно работающую голову или пол. Нативный inference не прерывается посреди вызова.

В head_turn_result записываются head_status/head_turn, body_status/body_reason, body_yaw_degrees, body_mirror_difference, body_weight и итоговый turn. В основном отчёте видны числа «корпус учтён / только голова».
